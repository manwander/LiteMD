# LiteMD 代码体检报告

- 项目：LiteMD v2.0.3（Tauri 2 + Svelte 5 legacy 模式 + CodeMirror 6，Rust 后端）
- 规模：前端 ~19,000 行（App.svelte 5280 / FileTree.svelte 1627 / editor.ts 1256 …），后端 ~23,400 行（lib.rs 3382 / sync/engine.rs 1781 / sync/webdav.rs 970 …）
- 审查范围：全部生产源码（`src/**`、`src-tauri/src/**`），不含 `dist/`、`node_modules/`、`target/`、`.cargo-tmp/`、测试快照产物
- 判定原则：每条「严重」及关键「中等」均由审查者亲自打开对应行复核；未逐行复核的长尾「轻微」项来自整文件通读，标注为可复核位置
- 严重程度定义：严重＝数据丢失/凭据外泄/安全边界失效/核心功能静默失效；中等＝真实缺陷或可度量性能/设计问题；轻微＝可维护性/打磨项

## 维度一 · 功能正确性

### 【严重】1-A 预览图片「收编到附件」引用改写功能静默失效（前端 sanitize 与注入自相矛盾）
- 位置：`src/App.svelte:233`（注入 `data-md-ref`）、`src/sanitize.ts:235-236`（`ADD_ATTR` 白名单不含该属性、`ALLOW_DATA_ATTR: false`）、`src/App.svelte:1202` 与 `1309/1328`（读取/判定/改写）
- 复核结论：`data-md-ref` 在 `sanitizeHtml` 阶段被 DOMPurify 剥离（白名单只有 `data-src`），预览 DOM 里恒无该属性；`openPreviewCtx` 因此回退读 `src`。Windows 下 `src` 是 `convertFileSrc()` 产出的 `http://asset.localhost/...`，在 `savePreviewImage` 中被 `/^(https?:|data:)/i`（1309）判为**外链** → 走 `fetch(ref)` 重新下载一份本地附件 → `importAssetRaw` 生成第二个副本；而改写正文的分支 `if (view && !isRemote)`（1328）恒 false。
- 影响：用户点「图片保存到附件」看到「图片已保存到附件」，但正文引用**一字未改**，附件目录多一个孤儿重复文件；`data-md-src`（`preview-edit-keys.ts` 设置、`App.svelte:2941` 读取）同理被剥离，预览编辑回写只能退化到 asset 前缀还原分支。
- 建议：`ADD_ATTR` 追加 `"data-md-ref","data-md-src"`；在 `ensureHooks()` 的 `afterSanitizeAttributes` 里对这两个值做约束（禁 `javascript:`、限长）；`savePreviewImage` 的外链判定不应把 `asset.localhost` 当远程；补 `sanitize.test.ts` 断言 `safeRender(md,"![](a.png)")` 结果含 `data-md-ref`。

### 【严重】1-B 上传 TOCTOU：读内容与 stat 非原子，可将新编辑永久丢失
- 位置：`src-tauri/src/sync/engine.rs:811-813` 读 v1 字节、`832-843` 以 v1 哈希 + v2 元数据落快照
- 复核结论：`bytes=read_bytes(...)`（811，大文件耗时）与 `st=stat_of(...)`（813）之间若用户再次保存，`hash` 属于 v1 而写入快照的 `size/mtime`（836-837）属于 v2。下一轮 `local_maybe_changed`（118-123）比较 size+mtime 相等 → 判定「未变」→ 跳过（229-230），v2 永不上传，远端停留 v1。`do_conflict` KeepBoth（`906/960`）同构。
- 影响：静默、单向、永久地丢失一次编辑；大文件/慢盘窗口更宽。
- 建议：`stat→read→再 stat`，两次 mtime 不同则重读重试；或对句柄 `File::metadata()` 与读取字节同源；小文件直接以哈希终审入 plan。

### 【严重】1-C 专注模式/收起侧栏会停掉全局 fs 监视，绕过外部变更覆盖保护
- 位置：`src/FileTree.svelte:1293`（destructor 调 `stopWatching()`）、`src/filetree/watcher.ts:76-92`（模块级单例 `unlisten`+`watchStop()` 关 Rust 监视器）、`src/App.svelte:4789`（`{#if showTree}` 包裹 FileTree）、`src/App.svelte:2618`（`toggleFocus` 置 `showTree=false`）、`src/App.svelte:2140`（App 另有独立 `listen("fs-change")`→`queueFsReconcile`）
- 复核结论：Rust 监视器的生命周期归 FileTree 所有；App 自己的外部变更协调（干净标签重载、脏标签标冲突，即 P1-1 安全门）虽仍注册，但事件源被关。进入专注模式后外部编辑器改文件 → 应用无感知 → 用户保存直接覆盖外部修改。
- 影响：绕过分歧检测（无冲突副本、无提示）导致外部修改被静默覆盖丢失。
- 建议：把 `startWatching/stopWatching` 生命周期上提到 App，FileTree 仅注册/注销回调；监视器仅在 App 卸载时停。

### 【中等】1-D 秒级 mtime 截断 + 等长编辑 → 改动被判定「未变」而漏同步
- 位置：`src-tauri/src/sync/engine.rs:118-123` 与 `229-230`（`(false,false)=>{}` 直接跳过、不进哈希终审）；`src-tauri/src/sync/local.rs:97-102`（`as_secs()` 截断）
- 复核结论：`local_maybe_changed` 只比 `size != s.size || mtime != s.mtime`，mtime 双方都是秒。同一秒内把内容改成等长（`02:00`→`02:01`）时 size 相等、秒级 mtime 相等 → 判未变并 `#4 跳过`。第 117 行注释「runtime 再做哈希终审」对根本未入 plan 的文件不成立。
- 影响：窄但真实；改到不同秒或不同长度才收敛。
- 建议：md 小文件上传路径直接哈希；或 mtime 用纳秒；或脏标签/编辑时间窗内强制入 plan。

### 【中等】1-E dry-run 被强制模式静默忽略，可执行破坏性全量同步
- 位置：`src-tauri/src/sync/mod.rs:295-305`
- 复核结论：`Some("forceUpload")/Some("forceDownload")`（296-297）优先于 `_` 分支里的 `dry_run` 判定（298-304）。若前端「预览强制同步」同时传 `dry_run=true`+force mode，会直接真实全量上传/下载并做回收站清理。
- 影响：预览操作产生不可逆副作用（取决于前端是否这样调用；后端未自防）。
- 建议：`dry_run` 具一票否决：force+dry_run 时只出计划不落动作，或显式报错。

### 【中等】1-F `max_file_size_mb = 0` 语义反转：本应「不限」实为「全部超限」
- 位置：`src-tauri/src/sync/mod.rs:152`（`unwrap_or(100)` 但无下限钳制）与 `src-tauri/src/sync/local.rs:83`（`meta.len() > max_file_size`）
- 影响：0 使**所有**文件进 skipped/omitted，远端反被全量下载，删除判定全押 omitted 护栏。
- 建议：命令入口 `max_file_size_mb.max(1)` 或显式定义 0=不限并让 scan 侧同步语义（对比 `concurrency` 已有 `clamp(1,16)`，`mod.rs:146`）。

### 【中等】1-G etag 未归一弱验证前缀 `W/`，可致每轮全量重下
- 位置：`src-tauri/src/sync/webdav.rs:530`（PUT 响应）与 `748`（PROPFIND getetag），两处都只 `trim_matches('"')`，无 `strip_prefix("W/")`
- 影响：服务器 PUT 回强 ETag、PROPFIND 回弱 ETag（常见）时二者永不相等 → `remote_maybe_changed`（engine.rs:131-134）每轮判变 → 每轮 GET 全部字节（写盘被 `do_download` 哈希去重挡住，但网络白费）。
- 建议：统一 `strip_prefix("W/")` + 去引号后再比较。

### 【中等】1-H 确认框/输入框单槽覆盖 → 前一个 await 永不 resolve（Promise 泄漏 + 模态叠层）
- 位置：`src/App.svelte:1160-1178`（`askConfirm`）、`1121-1149`（`askPrompt`）
- 复核结论：`confirmState = {... resolve}` 无「已有 pending」检查；第二个确认到达即丢弃第一个 `resolve`，其调用方 `await` 永久挂起。可达：`onCloseAllSave` 的「外部修改」确认期间在文件树按 Delete 触发 `batchDelete`（902）。模板另有 5 处独立 `{#if ...ConfirmModal}`（5127/5139/5151/5166/5180）可同时为真叠层、z-index 相同、Esc 互抢。
- 建议：合并为单一队列（复用 `tab-close-queue.ts` 思路），模板只留一处；`askConfirm` pending 时 reject 或入队。

### 【中等】1-I FileTree 卸载不清理拖拽态：`user-select:none` 永久残留 + 悬浮镜像挂 body
- 位置：`src/FileTree.svelte:1286-1296`（destructor 未调 `cleanupDrag`）、`374-392`（`cleanupDrag` 内容）
- 复核结论：destructor 漏 `document.body.style.userSelect=""`（387）、`dragPreview.remove()`（388-390）、`dragExpandTimer`（383-385）。拖拽中途失去 `showTree`（拖文件时进专注模式/弹模态触发重建）→ 全应用再也选不中文字，须重启；每次重挂再叠一个 `position:fixed;z-index:9999` 幽灵节点。
- 建议：destructor 调 `cleanupDrag()` 并纳入 `dragExpandTimer`/`scrollRaf`。

### 【中等】1-J FileTree 重命名输入框无 autofocus，按键被列表处理器抢走
- 位置：`src/FileTree.svelte:1483-1490`（重命名 input，无 autofocus/bind）与 `129-131`（`onListKeydown` 按 `e.target.tagName` 放行输入框）
- 影响：焦点仍在 `<ul>`，`e.target` 非 INPUT → 守卫失效 → Enter/Delete/方向键触发列表操作而非往重命名框打字。
- 建议：`bind:this`+`tick().then(()=>input.select())`，或守卫改 `if (renaming) return`。

### 【中等】1-K `computeStats` 的 CJK/码点计数偏差
- 位置：`src/App.svelte:1873` 只认 CJK 统一表意+扩展 A（假名/Hangul/CJK 标点/扩展 B 全不计）；`1878` latin 判定；逐 UTF-16 码元遍历使 emoji 计 2；`c!==10` 未排除 `\r`（CRLF 每行多算 1）
- 建议：`for (const ch of text)` 按码点 + `/[\p{Script=Han}\p{Script=Hiragana}\p{Script=Katakana}\p{Script=Hangul}]/u`，行尾统一 `\r\n|\n|\r`。

### 【中等】1-L fence-index 只按反引号奇偶判定，代码块内含 ``` 会破坏 smartEnter
- 位置：`src/fence-index.ts:19-30`（`lineIsFenceOpen` 任意缩进后 ≥3 反引号即计数）与 `85-103`（`isInsideCodeBlock` 用 `f%2`）；消费方 `src/editor.ts:1157-1196`
- 复核结论：奇偶法无法区分开/闭栏，代码块内容里若有一行以 ``` 开头（写教程文档常见），其后奇偶全翻 → `smartEnter` 把「块内」误判「块外」走进引用/表格分支，`view.dispatch({insert:"\n\n"})` 插进代码块中间破坏源码。且不识别 `~~~`（与 `block-splitter.ts:146`、`outline.ts:23` 不一致）、不限制 ≤3 空格缩进、不校验闭栏长度/info string（CommonMark 要求）。
- 建议：统一一个 CommonMark 围栏状态机（记录围栏字符+长度、闭栏须 ≥ 开栏长度且后仅空白、跳过 ≥4 空格缩进行），`fence-index`/`block-splitter`/`outline`/`smartEnter` 共用。

### 【中等】1-M 删除围栏标记不触发脏标记 → 索引陈旧
- 位置：`src/editor.ts:404-413`
- 复核结论：`touchesFence` 只看新文档插入侧 `ins`；删掉整行 ``` 时 `fb===tb`（插入为空）→ `markFenceDirty()` 不执行，奇偶索引保持旧值。
- 建议：同时检查被删侧 `u.startState.doc.sliceString(fa,ta)` 含 `\n`/``` 即标脏。

### 【中等】1-N 模块级全局状态在「双编辑器并存」下串档
- 位置：`src/fence-index.ts:36-38`（`ck`/`dirty`/`rebuildScheduled`）与 `src/editor.ts:232/550-590`（`suppressListener` 全局布尔跨 `await`）
- 复核结论：预览编辑模式主 view 与备份 view 并存（`editor.ts:1069-1073` 注释确认）。`isInsideCodeBlock` 用的 `ck` 基线可能属于另一 doc；`setDocStreaming` 分片 `await yieldToEventLoop()`（579）期间 `suppressListener` 仍为 true，会一并抑制第二个 view 的事务 → 其 `onChange` 不触发，漏预览更新且漏自动保存。
- 建议：索引与抑制标志按 view/doc 实例隔离（Loading annotation / 实例字段）。

### 【中等】1-O 覆盖式移动先删目标再移动，中途失败即丢数据
- 位置：`src/FileTree.svelte:542-548`（`deletePath(target)` → `movePath/copyPath`）
- 影响：delete 成功而 move 失败（占用/跨卷/权限）时旧目标已进回收站、源仍在原地，catch 只 `refreshAllAffected`+「操作失败」，「覆盖」变成「删掉旧的」；多项目标无回滚。
- 建议：后端 `move_path` 带 `overwrite` 原子替换，或前端 `move→tmp` → `delete target` → `rename`；失败消息区分「已移动 i/n」。

### 【中等】1-P 混合批量删除：根目录在任何确认前就被移除
- 位置：`src/FileTree.svelte:890-902`（`removeRoot` 循环在 `await confirm` 之前）
- 影响：用户点「取消」（911 `if(!ok)return`）也回不来，确认文案不提根已被移除。
- 建议：确认先行，把移除根并入确认消息，确认后再执行两类操作。

### 【中等】1-Q 大文件流式切片按 UTF-16 码元，可切断代理对
- 位置：`src/chunk-ranges.ts:3-7`（`p+=chunk` 对齐）与 `src/editor.ts:576`（逐块 `text.slice`）
- 建议：切片对 `from` 做代理对齐（低代理则前移/后移到非中间），与 `diffRange`（`editor.ts:531-543`）一致；`chunk<=0` 加防御避免死循环。

### 【中等】1-R `restartWatch` 无并发/disposed 守卫，且空根不重启监视
- 位置：`src/FileTree.svelte:1183-1192`（`$: if (watchRootsKey) void restartWatch()`；`watchRootsKey===""` 时不调 → 不 `stopWatching`）
- 影响：移除所有根后旧监视器仍活；连续改根并发跑两 `restartWatch` 竞态可致「最终无人监听」；`await startWatching` 期间组件销毁 → Promise resolve 后又把全局监听与 Rust watcher 重启，回调引用已销毁 store。
- 建议：加自增 `watchSeq`+`disposed` 校验；空根显式 `stopWatching`；去掉真值门。

## 维度二 · 安全

### 【严重】2-A WebDAV `normalize_base` 手写词法解析可绕过「明文 http 仅本机」白名单
- 位置：`src-tauri/src/sync/webdav.rs:67-77`（authority 切分只 `find('/')`）与 `109-123`（`is_loopback_authority` 取 `rsplit('@')` 末段）
- 复核结论：authority 切分只认 `/`、不认 `\`；对 `http://evil.com:80\@localhost/x`，authority 得 `evil.com:80\@localhost`，`rsplit('@')` 取 `localhost` → 判定回环 → 放行明文 http。随后 `base_url`（104）交给 reqwest，`url` crate 按 WHATWG 把 `\` 当分隔符解析，真实主机可解析为 `evil.com`，Basic Auth 账号密码随明文 HTTP 发出。第 52-53 行注释宣称的「B 修复」被完整绕过。
- 影响：诱导配置特定 URL 可使口令经明文链路外发（SSRF/凭据外泄面）。
- 建议：用 `url::Url::parse` 解析出 host 再判回环，拒绝含 `\`/userinfo/fragment/query 的 authority；不要手写词法与真实 HTTP 客户端解析器保持两套逻辑。

### 【中等】2-B WebDAV 口令全链路明文持久化，且含密结构体可被 Debug 打印泄露
- 位置：`src-tauri/src/sync/mod.rs:31-39`（`AccountDto` 密码每次 invoke 明文传入）、`settings.json` 明文持久化（与既有设计一致，见 `WebDAV同步-设计方案.md`）、`lib.rs:2836-2841`；`mod.rs:31`/`webdav.rs:27` 均 `#[derive(Debug)]` 且无 `Zeroize`/脱敏
- 影响：任何一次 `{:?}`/日志误印即泄露口令；磁盘明文。
- 建议：迁移到 Windows Credential Manager（`keyring`/`windows` crate）；为含密结构体手写 Debug 脱敏并实现 `Drop` 擦除。（若产品明确接受明文落盘，至少补 Debug 脱敏这一低成本纵深。）

### 【中等】2-C `danger_accept_invalid_certs(true)` 一键关闭证书校验，叠加 Basic Auth 即可被 MITM
- 位置：`src-tauri/src/sync/webdav.rs:132-134`（`ignore_tls_errors` 用户开关）
- 影响：属 opt-in，但与 2-B 口令组合即口令可被中间人截获；`sync_check_config` 不提示该状态。
- 建议：UI 强警示；开启时禁用口令或至少每次醒目提示；检查结果反映该状态。

### 【中等】2-D 绝对路径全开放写/删：前端 IPC 无工作区包含性校验，纵深不足
- 位置：`src-tauri/src/lib.rs:28-57`（`validate_path` 只做词法消解 `..`，注释 30-34 明确绝对路径原样放行）；`src/FileTree.svelte:770-780`（`createFile(\`${target}/${fname}\`)` 的 `target` 来自 PromptModal 可编辑绝对路径，未校验）
